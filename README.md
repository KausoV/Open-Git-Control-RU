# Open Git Control RU

Независимая общественная локализация [Open Git Control](https://github.com/timbornemann/Open-Git-Control) с интерфейсом **English (Русский)**: оригинальная английская подпись и русский перевод в скобках. Например, `Settings (Настройки)` и `Commit (Коммит)`.

Это не официальный выпуск Tim Bornemann и не аффилированный с автором проект. Основа — Open Git Control **3.2.3**, коммит [`99e475f40a5497e971fa212014ffabe092c4ef78`](https://github.com/timbornemann/Open-Git-Control/commit/99e475f40a5497e971fa212014ffabe092c4ef78). Метка первого выпуска перевода — **`v3.2.3-ru.1`**; внутренняя версия исходного приложения остаётся `3.2.3`.

## Скачать и запустить

1. Установите [Git for Windows](https://git-scm.com/downloads/win), если Git ещё не установлен. Команда `git --version` должна работать в терминале. Если программа была открыта во время установки Git, перезапустите её.
2. Откройте [выпуск v3.2.3-ru.1](https://github.com/KausoV/Open-Git-Control-RU/releases/tag/v3.2.3-ru.1). Внизу страницы, в **Assets**, скачайте **`Open-Git-Control-3.2.3-ru.1-win-x64-portable.zip`**. Пункты `Source code (zip)` и `Source code (tar.gz)` содержат исходники для сборки, а готовая программа находится в архиве с `portable` в названии.
3. Нажмите на скачанном ZIP правой кнопкой мыши → **Извлечь всё**. Распакуйте архив целиком в папку, доступную для записи. Все файлы должны оставаться вместе; запуск из окна архива не подходит.
4. Откройте распакованную папку `Open-Git-Control-3.2.3-ru.1-win-x64` и дважды нажмите **`Start-Open-Git-Control-RU.cmd`**. Также можно открыть `app/Open-Git-Control.exe`.
5. В настройках выберите **English + Russian (Русский)**, если этот режим ещё не выбран. Дальше можно добавить свой проект или клонировать существующий — инструкции ниже.

Сборка предназначена для **Windows 10/11 x64**. Это настольное приложение Electron; установка Node.js, npm, Python или Rust для запуска готового архива не требуется. Основа использует Electron 43; минимальная версия Windows соответствует [требованиям Electron](https://www.electronjs.org/docs/latest/breaking-changes#removed-windows-7881-support).

**Для скачивания программы, запуска и локальной работы вход в GitHub не нужен.** Просматривать публичные проекты на GitHub и клонировать их по публичной HTTPS-ссылке тоже можно без входа. Для отправки изменений в GitHub каждый человек использует **свою** учётную запись с доступом к целевому репозиторию.

Настройки и данные входа создаются в `app/user-data` рядом с программой. Архив выпуска не содержит пользовательского профиля. Для передачи программы используйте ссылку на релиз; свою папку `user-data` оставляйте у себя.

## Подключить свой GitHub для отправки изменений

Ниже — вариант с персональным токеном для HTTPS. Если в системе уже настроен работающий Git/SSH-доступ, приложение также умеет использовать его.

1. В своём аккаунте GitHub откройте **Settings → Developer settings → Personal access tokens → Fine-grained tokens** и создайте токен. Для работы со своим проектом выберите свой аккаунт в **Resource owner**, затем **Only select repositories** и нужный репозиторий. Если его ещё нет, сначала создайте репозиторий на GitHub.
2. В **Repository permissions** установите **Contents → Read and write** и сохраните токен. Это разрешение для обычной работы с содержимым выбранного репозитория; у отдельных функций GitHub могут быть дополнительные требования. При изменении существующего токена сохраните обновлённые разрешения. [Настройка токенов в документации GitHub](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens).
3. В приложении откройте **Settings (Настройки) → Accounts & servers (Учётные записи и серверы) → Add connection**. Выберите GitHub, сервер `https://github.com`, способ **Token**, вставьте свой токен в поле токена и нажмите **Connect this account**. Проверьте, что указан ваш аккаунт и статус **Connected**. Токен вводится только в предназначенное для него поле: не отправляйте его в чат, Issues или README.
4. Откройте локальный репозиторий и раздел **Remote configuration (Настройка удалённых репозиториев)**. Выберите `origin` — это обычное имя связи с репозиторием на GitHub. Проверьте адрес вида `https://github.com/OWNER/REPOSITORY.git`.
5. Откройте **Access for this remote (Доступ к этому удалённому репозиторию) → Change access (Изменить доступ)**. Выберите свой аккаунт, нажмите **Assign app account (Назначить учётную запись приложения)** для нужного адреса, затем **Save (Сохранить)** внизу страницы. Если адреса Fetch и Push различаются, проверьте назначение именно для адреса Push.

После сохранения назначенный аккаунт используется для Git-передач по HTTPS. Один лишь вход в раздел аккаунтов не назначает его автоматически каждому `origin`; при затруднениях с Push проверьте шаги 4–5 и разрешение `Contents: Read and write` для этого репозитория. SSH-адреса используют отдельно настроенный SSH-ключ или агент.

Токен действует в пределах прав его владельца: он **не даёт права изменять чужой репозиторий** только потому, что в нём выбран `Read and write`. Доступ определяется также владельцем проекта и правилами ветки. [Как устроены права токена](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens#about-personal-access-tokens).

## Начать со своим проектом

1. Нажмите **Add repository (Добавить репозиторий)** и выберите папку своего проекта. Если в ней ещё нет Git-репозитория, подтвердите **Initialize repository (Инициализировать репозиторий)**. Если программа запросит имя и email автора коммитов, укажите свои данные.
2. Откройте список изменений и проверьте файлы. Добавьте нужные изменения в индекс действием **Stage (В индекс)** — так выбирается содержимое следующего коммита.
3. Напишите короткое описание изменений и нажмите **Commit (Коммит)**. Коммит сохраняет выбранные изменения в локальной истории; интернет для этого не нужен.
4. Для первой публикации создайте на GitHub **пустой** репозиторий в своём аккаунте. Для уже существующего локального проекта оставьте создание README, `.gitignore` и лицензии на GitHub выключенным, чтобы не создавать отдельную начальную историю. Скопируйте HTTPS-адрес нового репозитория.
5. В **Remote configuration → Add remote** добавьте связь с именем `origin` и этим адресом. Подключите к ней свой аккаунт по инструкции выше. Если репозиторий создан после токена, добавьте его в список разрешённых репозиториев токена.
6. Нажмите **Push (Отправить)** и выберите нужную ветку, если приложение попросит. Затем откройте репозиторий на GitHub и проверьте, что коммит появился.

Для последующих изменений повторяйте **Stage → Commit → Push**. Если над проектом работают несколько человек, сначала получите изменения коллег через **Pull (Получить изменения)**; при конфликте приложение покажет файлы, которые нужно согласовать.

## Работать с чужим проектом

Чтобы изучить публичный проект, скопируйте его HTTPS-ссылку на GitHub и используйте **Clone repository from URL (Клонировать репозиторий по URL)**. Выберите папку на своём компьютере. Клонирование создаёт локальную копию и не меняет исходный проект.

Чтобы предложить исправление автору:

1. Войдите в **свой** GitHub и нажмите **Fork** на странице исходного проекта. Появится копия проекта под вашим аккаунтом.
2. Клонируйте свой fork в приложение, создайте отдельную ветку и внесите изменения.
3. Выполните **Stage → Commit → Push** в свой fork. Для токена выберите именно этот репозиторий, а его HTTPS-адрес назначьте как `origin`.
4. На GitHub откройте **Pull request** из своей ветки в исходный проект. Автор рассмотрит предложение и решит, включать ли его. [Инструкция GitHub по fork](https://docs.github.com/en/pull-requests/how-tos/work-with-forks/fork-a-repo).

Отправлять изменения напрямую в исходный репозиторий можно только при предоставленном владельцем доступе и с учётом правил проекта. Возможности токена сами по себе такой доступ не предоставляют.

## Что изменено

- Английские подписи дополнены русским переводом в основном интерфейсе, диалогах и контекстных меню.
- Сохранены значения команд Git, пути, URL, имена протоколов и заполнители параметров.
- Пояснения в генерируемых инструкциях могут быть двуязычными; JSON и команды не дублируются.
- Длинные двуязычные подписи переносятся в кнопках и вкладках.
- Профиль хранится внутри переносимой папки приложения. Автоматическая установка официальных обновлений отключена по умолчанию, чтобы сохранить локализацию.

Содержание заметок о выпусках и отдельный выбор языка для результатов ИИ сохраняют возможности оригинала (`de`/`en`). Вспомогательная программа **Recovery** остаётся оригинальной, без русского перевода. Она относится к официальным выпускам; обновления этой локализации следует брать со страницы выпусков данного репозитория.
